First run of the redis-restart scenario: restarting Redis made `vsworker` exit with `save state: LOADING Redis is loading the dataset in memory` (no retry), so the real-time consumer group stalled at ~6M records of lag until the run was aborted. Fixed by bounded exponential back-off retries around state load/save (offsets are only committed after the state is saved); the alert service got the same treatment. The scenario was re-run after the fix (`../redis-restart`). The run did not complete, so there is no result.json here.
