# Gate G2: deterministic 100K-vehicle simulator

Rows covered: MB1, T1, D6, D7. Evidence: `evidence/G2/`.

## What is built
`internal/roadnet` synthetic city road graphs (Chennai, Bengaluru, Surat; ~48K nodes each) · `internal/sim` physics-based fleet engine (sharded, per-vehicle PRNG, 1 Hz telemetry, shift-start surge, trips, low-SoC charging, strandings, charger outages, injections) · `cmd/vssim` CLI. The fleet is the same 100,000 vehicles (VINs, tenants, fleets, depots, chargers) as the database seed.

## Acceptance criteria
| # | Criterion | Verification |
|---|---|---|
| G2.1 | Deterministic: same seed -> identical output (order-independent digest and per-vehicle sequence), independent of shard count; different seed -> different | unit test |
| G2.2 | Road graphs are connected and nearest-node snapping is correct | unit test |
| G2.3 | Encoders: hand-written protobuf encoding equals `proto.Marshal`; both OEM JSON dialects (A v1/v2, B) are valid and carry every field | unit test |
| G2.4 | Injection rates match their flags within tolerance: duplicates, out-of-order, malformed; outage buffering produces a flush burst; burst window multiplies the event rate | unit test |
| G2.5 | Physics sanity: SoC falls while driving and rises while charging, speeds plausible, positions inside the city, per-VIN `seq` monotonic, strandings occur under a stress scenario and are written to ground truth | unit test |
| G2.6 | Ground-truth files (vehicle truth, trips, charge sessions, strandings) are written | unit test |
| G2.7 | 100,000 vehicles run in one process; memory footprint measured; **generator throughput measured** with a null sink (target > 150K events/s so the generator is never the bottleneck) | benchmark run, `evidence/G2/sim_benchmark.json` |

## Out of scope here
Delivery to the gateway/Kafka (M3). Real-time pacing is implemented and tested for rate; end-to-end rates are measured at G14.
