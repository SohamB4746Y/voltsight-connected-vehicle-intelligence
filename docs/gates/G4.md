# Gate G4/G5: stream worker and storage sinks

Rows covered: AL7, AL8, AL9 (sliding window, Bloom, Count-Min), SD4/SD5/SD9 (idempotency, at-least-once, replay), T4, D5, SC5. Evidence: `evidence/G4/`.

## Design
`telemetry.v1` is consumed by two independent consumer groups. **`rt-processor`** (`internal/rtp`, `cmd/vsworker`) keeps the authoritative per-vehicle state in Redis (`t:<tenant>:v:<vin>`: latest event, highest seq, 256-bit seen-window) with a local write-behind cache per owned partition. **`sink`** (`internal/sink`, `cmd/vssink`) batch-inserts raw telemetry into ClickHouse (`ReplacingMergeTree`, partitioned by day, ordered by tenant/vin/ts/seq). Semantics are **at-least-once**: offsets are committed only after state has been flushed to Redis (worker) / the batch was inserted (sink); replays are harmless because state updates are seq-guarded and the ClickHouse sorting key makes duplicates collapse.

## Acceptance criteria
| # | Criterion | Verification |
|---|---|---|
| G4.1 | Exact dedup window: no duplicate is ever treated as new, no new event is ever treated as duplicate, for in-window out-of-order delivery; property test against a reference set | unit/property test |
| G4.2 | Bloom filter: no false negatives; measured false-positive rate matches theory; rotation keeps memory bounded | unit test |
| G4.3 | Count-Min Sketch + heap: estimates never under-count; error within the (eps, delta) bound; top-K recall measured | unit test |
| G4.4 | Worker correctness on a real Kafka + Redis: with injected duplicates and out-of-order events the per-VIN latest state equals the highest-seq event, duplicates are counted and not applied, stale events do not regress state | integration test |
| G4.5 | Replay rebuilds identical state: wipe Redis, reprocess the topic from the beginning with a new group, state hash identical | integration test |
| G4.6 | Crash safety: kill the worker mid-stream (no clean shutdown), restart in the same group; final state identical to an uninterrupted run; nothing lost | integration test |
| G4.7 | Sink: events inserted into ClickHouse; row count equals the topic count (duplicates included) before merge and the distinct count after `FINAL`; partitions by day; no insert exceeds the part limit | integration test |
| G4.8 | Reconciliation: Kafka accepted == worker processed == ClickHouse rows (+ DLQ accounted) after an end-to-end run | `cmd/vsrecon` run |
| G4.9 | Lag stays bounded at the real-time rate (100K events/s) for a measured duration; throughput and CPU of each stage measured | measurement |

Deferred: Parquet cold archive (written with the batch milestone M7, which is its first consumer).
