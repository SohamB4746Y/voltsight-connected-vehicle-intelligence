# Gate G3: ingest gateway and Kafka

Rows covered: T2, T4 (partitioned durable stream), X4 (OEM schema rollout), AL5/AL6 (VIN and OBD-II DTC parsing), N14 (device mTLS), SD6 (back-pressure). Evidence: `evidence/G3/`.

## Design
HTTPS/2 + **mTLS (TLS 1.3 only)**: one client certificate per OEM-cloud connector (tenant x OEM), issued by Vault; the gateway also requires the certificate's fingerprint to be registered and active in `device_credential` and not on the CRL. Tenant and OEM come **only** from the certificate. Per event: decode (protobuf or the connector's OEM JSON dialect) -> validate -> normalise -> Kafka (`telemetry.v1`, key = VIN, idempotent producer, acks=all, lz4); failures go to `telemetry.dlq.v1` with the original bytes. A 200 is returned only after Kafka acknowledged every accepted event. Back-pressure: in-flight byte budget and a per-connector event-rate limiter answer 429 + `Retry-After` before anything is produced; Kafka unavailability answers 503.

## Acceptance criteria
| # | Criterion | Verification |
|---|---|---|
| G3.1 | OBD-II DTC and VIN parsing: raw 2-byte OEM codes decode to P/C/B/U codes; malformed rejected; property/fuzz-style round trips | unit tests |
| G3.2 | OEM A (v1, v2) and B payloads normalise to the same contract; unknown schema, missing required fields and out-of-range values are rejected with the right DLQ class | unit tests |
| G3.3 | mTLS: no certificate, wrong CA, expired, revoked (CRL), and unregistered certificates are all rejected at the handshake; TLS < 1.3 is refused | integration test (real Vault) |
| G3.4 | Tenant is derived from the certificate: a forged `tenant_id` in the payload is overwritten; a VIN belonging to another tenant goes to the DLQ as UNAUTHORIZED_VIN | integration test (real Kafka + DB) |
| G3.5 | Per-event validation isolates failures: in a mixed batch only the bad events reach the DLQ with the right class; the rest are accepted and present on `telemetry.v1` keyed by VIN | integration test |
| G3.6 | End to end: the simulator (proto and OEM JSON, with injected duplicates/out-of-order/malformed) delivers through the gateway; accepted + DLQ equals sent; duplicates and out-of-order events are passed through (not dropped); the schema-v2 rollout mid-run causes zero rejects | integration test |
| G3.7 | Back-pressure: with a tiny in-flight budget concurrent requests get 429 with `Retry-After`, and the retrying sender eventually delivers everything with no loss | integration test |
| G3.8 | Kafka topics exist with the designed partitions/retention/compaction; same VIN always lands on the same partition | integration test |
| G3.9 | Gateway-alone throughput measured (sim -> gateway -> Kafka) | measurement, `evidence/G3` (MEASURED, not a target claim) |

## Deferred (stated)
Exactly-once to Kafka is not claimed (at-least-once + dedup downstream, ADR-003). Hot-reloadable OEM mapping registry: dialect parsers are compiled in; adding an OEM needs a deploy of the gateway (limitation recorded). Kafka broker failure behaviour is tested at G13.
