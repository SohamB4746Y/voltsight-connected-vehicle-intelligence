# Gate G1 — Contracts, PostgreSQL core, security base, 100K seed

Written before implementation. Evidence: `evidence/G1/<UTC>-<sha>/`. Covers matrix rows D1, D2, D13, T3, SC1, SC6, DL4, DL6, N11 (realm), N13 (DB layer), N14 (CA part), TS3 (first Testcontainers use).

## Decisions fixed by this gate
- **ADR-006 tenant isolation:** every tenant-scoped table carries `tenant_id NOT NULL`; child tables reference parents with **composite FKs `(tenant_id, parent_id)`** so a row can never point at another tenant's parent. RLS policy: `tenant_id = current_setting('app.tenant_id', true)::uuid` (fail-closed when unset). This is a *deliberate documented denormalisation* (tenant is derivable via the parent) whose integrity is enforced by the FK, so it cannot drift. Shared reference data (vehicle models, public chargers, tariff zones) have `tenant_id NULL` or no tenant and are read-only to the app role.
- **Device identity:** one mTLS client certificate per *OEM-cloud connector* (tenant × OEM), issued by a Vault PKI engine; identity carried in a URI SAN `spiffe://voltsight/tenant/<uuid>/oem/<name>`. VIN→tenant authorisation is checked by the gateway against `vehicle`.
- **Wire field names** follow the PDF example (`vin, ts, lat, lon, speed_kmh, soc_pct, odo_km, dtc, evt, seq`) so the PDF's JSON parses unchanged.
- **Roles:** `voltsight` (migration owner, superuser in dev only), `voltsight_app` (API; RLS-bound), `voltsight_gateway`, `voltsight_batch`, `voltsight_privacy`, `voltsight_sealer` (audit hash-chain). None except the owner may DDL; none has BYPASSRLS.
