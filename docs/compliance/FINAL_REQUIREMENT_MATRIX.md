# Final requirement matrix

Source of truth: the Motorq Connected Vehicle Intelligence problem statement (sections 6-14). Each row is machine-checked by `go run ./tools/reqtrace` (also a CI step): a **PASS** needs an implementation, a verification command and evidence paths that exist; every other status needs a stated gap; no status other than PASS, PARTIAL, BLOCKED, FAIL or NOT_APPLICABLE is accepted. The gate checks that evidence exists, not that the evidence says what the row claims: the claim is only as good as the cited file, which the reader can open.

Legend: **PASS** = implemented and evidenced; **PARTIAL** = implemented with a named gap; **BLOCKED** = needs something this environment cannot do (credentials, an account, a human recording); **FAIL** = tried or specified and not achieved/absent; **NOT_APPLICABLE** = none used. Detailed status by gate: `docs/requirements-status.md`; judge-facing summary: `docs/compliance/FINAL_SUBMISSION_STATUS.md`.

Environment for all measurements: 4-vCPU / 15 GiB Linux sandbox with every component on one host unless stated.
