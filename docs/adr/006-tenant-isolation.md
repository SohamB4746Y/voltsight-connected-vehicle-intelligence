# ADR-006 Tenant isolation
**Decision:** shared schema + PostgreSQL **row-level security** (forced) keyed by a transaction-local `app.tenant_id` set from the verified JWT, plus explicit `tenant_id` predicates in every query (defence in depth: an RLS miss still cannot return foreign rows, and the predicate lets the planner use the tenant-leading indexes). ClickHouse queries are always bound to the tenant (named parameter) after an ownership check in PostgreSQL; Redis keys carry the tenant prefix; Kafka tenant comes from the device certificate; pgvector rows are RLS-protected. Rejected: schema-per-tenant (migration fan-out, connection pooling pain at hundreds of tenants).
**Evidence:** G1 attack suite (SELECT/INSERT/UPDATE/DELETE, joins, views, functions) incl. a mutation check that fails when the policy is weakened; API tests: foreign vehicle/alert/charger by id → 404, list endpoints never contain foreign rows, injection attempts inert.
**Measured:** the policy form `tenant_id = (SELECT app_tenant())` vs a bare function call showed **no meaningful difference** on 100K rows (9.9 vs 10.2 ms): documented in `evidence/G9b`.
